# 任务卡机制说明

> 总入口：根目录`AGENTS.md`。本目录（`docs/scaffold/`）是孵化脚手架层——可迁移方法论与任务卡机制，不承载本 MOD 的具体规则；具体规则以 `AGENTS.md`、`docs/maintenance/` 与各手册为准。

## 定位

任务卡是本仓库「孵化环境」的开工单元：任何新任务（新人物批次、新游戏版本发布、新接手）从一张卡开始，保证每次开工都有标准起点、有据可查。

## 三层分工（单一事实源）

| 层 | 文件 | 管什么 |
|---|---|---|
| 模板 | `workbench/templates/任务卡模板.md` | 卡的结构与三条流水线检查清单 |
| 卡 | `workbench/cards/<NNN>_<任务名>.md` | 单个任务的填空与过程细节（任务进行中看卡） |
| 交接 | `docs/maintenance/开发状态快照与交接.md` 变更记录 #n | 串级交接摘要（新串看快照） |

状态行与门一/门二/门三结论以快照变更记录为**单一事实源**；卡内只放任务细节与检查清单勾选。二者互相指针，不重复抄状态。

## 开工流程

1. 判级（A/B/C，见《维护与重构标准流程_适配版》三问定档）。
2. 复制模板为 `workbench/cards/<NNN>_<任务名>.md`（编号顺延现有卡）。
3. 门一需求对齐后填卡第二节；门二方案拍板后填第三节；K3 每轮填第四节；门三结案填第五节。
4. 同步在快照文档追加「变更记录 #n」，状态行引用卡号。
5. 结案后卡留在 `cards/` 备查（git 历史即完整轨迹），不另设归档。

## 三条流水线

- **新人物小传批次**：底账/名单 → `<idea_token>_desc` 自动显示路径口径复核 → 身份裁定（真人/占位/同名混淆）→ 正文起草（`workbench/pending_text/`）→ 人工审定（`workbench/approved_text/`）→ 入包 → 审计 → K3 → 门三。
- **新游戏版本发布**：原版参考配置 → `src/full_only/` 以新原版为底重建 → 七国历史文件重新语义审计 → 全量审计（含原版语义比对）→ 实机回归 → 基准更新 → 发布闸门。
- **新接手串**：读链五步 → `git status --short` → 环境核对并更新快照 1.1 → `python tools/audit_all.py` 留底 → 承接未决待办。

各流水线的细化检查清单见 `workbench/templates/任务卡模板.md` 对应节。
