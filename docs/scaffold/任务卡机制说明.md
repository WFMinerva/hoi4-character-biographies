# 任务卡机制说明

> 总入口：根目录`AGENTS.md`。本目录（`docs/scaffold/`）是孵化脚手架层——可迁移方法论与任务卡机制，不承载本 MOD 的具体规则；具体规则以 `AGENTS.md`、`docs/maintenance/` 与各手册为准。

## 定位

任务卡仅用于高风险任务中需要跨对话、跨多步骤推进或确有复杂决策需要持久交接的情形（高风险清单见《维护与重构标准流程_适配版》高风险通道）。普通讨论、只读检查与小型变更不建卡；高风险任务即使不建卡，其需求门、方案门、验证与提交前独立复验仍必须执行——卡只是留痕载体，不是流程本身。

## 记录分工

| 层 | 文件 | 管什么 |
|---|---|---|
| 模板 | `workbench/templates/任务卡模板.md` | 卡的结构与三条流水线检查清单 |
| 卡 | `workbench/cards/<NNN>_<任务名>.md` | 单个高风险任务的需求/方案/验证/复验/结案记录 |

卡即任务记录本身；结案后卡留在 `cards/` 备查（git 历史即完整轨迹），不向任何滚动流水账同步，不另设归档。

## 开工流程

1. 确认任务命中高风险清单，且需要跨对话、跨多步骤推进或持久交接。
2. 复制模板为 `workbench/cards/<NNN>_<任务名>.md`（编号顺延现有卡）。
3. 需求门拍板后填卡第二节；方案门拍板后填第三节；独立复验每轮填第四节；机主确认提交后填第五节结案。

## 两条流水线

- **新人物小传批次**：底账/名单 → `<idea_token>_desc` 自动显示路径口径复核 → 身份裁定（真人/占位/同名混淆）→ 正文起草（`workbench/pending_text/`）→ 人工审定（`workbench/approved_text/`）→ 入包 → 审计 → 提交前独立复验 → 机主确认。
- **新游戏版本发布**：原版参考配置 → `src/full_only/` 以新原版为底重建 → 七国历史文件重新语义审计 → 全量审计（含原版语义比对）→ 实机回归 → 基准更新 → 发布闸门。

新接手或新对话本身不是高风险任务，不建卡：直接读根 `AGENTS.md`、`git status --short`、按当前任务取读权威文档即可。

各流水线的细化检查清单见 `workbench/templates/任务卡模板.md` 对应节。
