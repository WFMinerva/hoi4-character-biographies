## 3. 拍板口令与状态词汇（您只需要说这几个词）

| 您说 | 含义 |
|---|---|
| 「拍板」「按方案执行」「开始」 | 该道门通过，AI 可推进到下一门 |
| 「推送」 | 唯一允许 git push 的口令；没有这两个字任何情况下不推送 |
| 「试玩没问题 / 没发现问题」 | 实机确认通过，AI 可据此更新基准卡、打 `*-stable` 标签（上传工坊前仍会再向您确认） |
| 「暂停」「先别动」 | 立即停在该门 |

AI 报告里的状态分级，只有您实机确认过的才是「实机确认/用户确认」；其余只是「文件确认/静态确认/日志确认」，别被文字混淆。

- **固定约定（2026-08-20 机主指定）**：每次到门，AI 报告同步给 2–4 个建议选项——推荐第一标「（推荐）」，每项一句取舍；您点选或回「选 n」/「按推荐」即拍板生效，自由回复不锁死；弹窗不可用降级正文编号列表；**推送永不进选项**。此约定对全部 AI 会话有效。

## 4. 只有您能做的三件事

1. **实机测试**：AI 部署测试包后，您进游戏开 1936/1939 剧本点验，结束后**不用转发日志**——AI 直接从游戏用户目录 `logs\`（路径以《开发状态快照与交接》1.1 为准；本机未装游戏，在您实测的机器上）读取判读（error.log / text.log / game.log / setup.log）。
2. **黄金存档**：每轮回归从黄金存档出发（1936/1939 各一份），实测后另存判定档（如 `cbio_gold36_v130e-test1.hoi4`，命名口径见 `docs/testing/黄金存档制度_钢四裁剪版.md` §二.1），不覆盖原档；AI 负责登记哈希。建档时进游戏开局后保存为 `cbio_gold36.hoi4`、`cbio_gold39.hoi4` 即可。
3. **工坊上传**：AI 准备到登录前（构建包、逐文件哈希核对、VDF、changenote），然后您本人执行（密码与 Steam Guard 验证码只您输入，不写入任何文件、不告诉 AI）。命令模板（在您装有 steamcmd 的机器上执行，路径以《开发状态快照与交接》1.1 为准）：
   ```powershell
   <steamcmd目录>\steamcmd.exe +login wendu1991 +workshop_build_item <steamcmd目录>\hoi4_china_bio_lite_<版本>.vdf +workshop_build_item <steamcmd目录>\hoi4_china_bio_full_<版本>.vdf +quit
   ```
   必须看到兼容版 `3736859636` 和完整版 `3762643540` **各自的** `Upload finished ... : OK`（只有一个 OK 不算完成）；最终以 `<steamcmd目录>\logs\workshop_log.txt` 为准。

## 5. 纪律速查（对您同样有效）

- 完整版和兼容版**不能同时启用**（二选一）。
- 未经您确认，AI 不会提交；没有「推送」二字，绝不推送。
- 旧包/旧表/旧报告不是当前基准——您指定的新基准永远优先。
- 出现「某人不显示小传」时，给 AI：人物名＋国家＋剧本＋（最好有截图），其余排查由 AI 做。
- AI 说「稳定版」前，必须您实机确认过；您没确认前只能是「测试包 / 阶段性可接受」。
