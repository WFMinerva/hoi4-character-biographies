# 人物小传文本处理手册

> 总入口：根目录`AGENTS.md`；当前版本状态以`docs/CURRENT_BASELINE.md`为准。

本文件保存项目长期形成的写作、清洗、复核和入包规则。

## 1. 基本目标

人物小传不是百科全书全文，也不是文学评价。目标是在HOI4悬浮框内，用一个连续段落交代：

1. 生卒与出身；
2. 进入政军体系的路径；
3. 1936—1945年前后的主要职务和行动；
4. 与游戏身份直接相关的历史位置；
5. 战后结局或死亡；
6. 必要的争议、罪责或史料不确定性。

## 2. 事实优先级

1. 用户已人工审定的正文；
2. 可核查的权威史料和多源一致事实；
3. 现有稳定版正文；
4. AI或外部写手草稿；
5. 机器推断。

AI草稿不能直接入包。人物同名、译名、出生地、军衔、任期和死亡日期有冲突时，必须标记待复核，不能用流畅措辞掩盖不确定性。

## 3. 分类裁定

- 真人：可进入写作、挂载和复用流程。
- C类领袖：可以人工审核后写入。
- C类非领袖：原则上不写。
- 占位或程序生成角色：不写小传；若原版简中给了误导性中文名，按已批准规则恢复拉丁字母原名。
- 科学家：默认不写，只保留机器底库。
- 虚构领袖：可在明确标注虚构的前提下处理；虚构非领袖默认不写。

## 4. 篇幅与结构

- 默认单段，不使用标题、项目符号和尾注。
- 一般人物控制在约150—500汉字；重要人物可适度超过，但要避免把完整传记塞入悬浮框。
- 先写确定事实，再写争议或评价。
- 不使用“他的一生充满传奇”“历史将永远铭记”等抽象总结句。
- 不编造内心活动、名言、临终对白和未经证实的具体数字。

## 5. 评价边界

- 对战争罪、殖民统治、政治迫害、附敌行为等，使用可核查事实与司法结论，不使用粉饰性语言。
- 不因人物属于某一阵营而自动英雄化或妖魔化。
- 对存在史学争议的行为，明确写“被指控”“某法庭认定”“史料存在分歧”等，不把争议写成无条件事实。
- 对用户已审定的价值判断，不得擅自弱化或强化。

## 6. 一人一文与别名

同一人物在领袖、顾问、将领、动态角色等多个入口出现时：

- 建立一个正文主键；
- 其他入口用`$主键$`别名；
- 修改时只维护主键；
- 不允许出现两个内容不同的正式正文。

傅作义是标准案例：`SHX_fu_zuoyi_desc`复用`CHI_fu_zuoyi_desc`。

## 7. 外部写手或Claude稿件清洗

导入前必须删除：

- `§Y姓名§!`等审稿标记；
- “自检”“资料来源”“写作说明”；
- Markdown标题、分隔线、表格；
- 多余引号和代码围栏；
- 同一人物的多版本备选稿；
- 无法确认的推测性句子。

保留用户明确选择的最终正文。清洗动作不等于事实审核。

## 8. 本地化写入

标准形式：

```yml
l_simp_chinese:
 CBIO_TAG_person_desc:0 "正文"
```

要求：

- UTF-8 BOM；
- 正文物理单行；
- key唯一；
- 需要兼容原版入口时建立别名，不复制正文；
- 先写正文，再挂`desc`，最后运行引用完整性检查。

## 9. 人工审核台账

每条拟入包文本至少记录：

- 人物key；
- 显示名；
- 国家Tag；
- 身份；
- 真人/占位/C类；
- 正文主键；
- 来源状态；
- 人工审核状态；
- 挂载路径；
- 两版本处理；
- 测试状态；
- 用户最终裁定。

机器扫描表是候选底库，不是最终裁定表。

## 10. 发布前文本检查

- 无重复key；
- 无空正文；
- 无审稿残留；
- 无别名循环；
- 新`desc`引用均有正文；
- 同一人物无冲突正文；
- 重要日期与身份完成抽查；
- 用户人工修订未被旧稿覆盖。
