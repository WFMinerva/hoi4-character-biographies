# 钢四人物小传MOD · 实机回归归档制度（钢四裁剪版）

> 状态：2026-08-20 门二已拍板（全量落地）并落地本仓库。
> 定位：移植《开局一键爽玩》`docs/testing/实机回归归档制度.md`，按本 MOD 裁剪。每轮进游戏实测的证据必须按本制度归档入库；缺证据的轮次判 `FAIL_NOT_EVIDENCED`，不得只记「机主结论」。
> 工具：判读统一走裁剪版 `tools/check_logs_cbio.py`（白名单过滤＋版本绑定＋result.json；本 MOD 无 `OCS_TEST` 自检机制，不适用标记铁律，见 §三）。

## 一、归档目录约定

每轮实机回归在 `docs/testing/<版本-轮次>/` 下归档（如 `docs/testing/v130e-test1/`），必含：

| 文件 | 内容 | 必需 |
|---|---|---|
| `README.md` | 轮次摘要：版本线、测试包 SHA-256、结论（通过/未通过）、问题清单、例外说明，并注明 result 位置 | 是 |
| `清单.md` | 逐项点验清单：每项「通过/未通过/未测」＋现象＋证据位置，逐项必填 | 是 |
| `logs/` | 四份日志（error.log/game.log/setup.log/text.log）脱敏副本；`code_revisions.log` 副本 | 是 |
| `screenshots/` | 截图，命名 `NN_<检查项简称>.png`（NN＝清单序号） | 涉及界面/视觉项时必填 |
| `SHA256SUMS.txt` | 归档内所有文件的 SHA-256 清单（行尾统一 LF） | 推荐 |

机器可读判定 `result.json` 由 `tools/check_logs_cbio.py` 输出到 `audit/reports/cbio_<轮次>.json`（按 `tools/AGENTS.md` 输出边界），`README.md` 引用其路径与判定结论。

## 二、逐项必填与 FAIL_NOT_EVIDENCED

1. `清单.md` 每一项必须有结论与证据位置；空栏＝该项未测。
2. 判定规则：
   - 项结论「通过」但无证据位置（日志行/截图/静态比对输出）→ 该项记 `FAIL_NOT_EVIDENCED`。
   - 任何一项 `FAIL_NOT_EVIDENCED` 或「未通过」→ 本轮不得判「实机通过」，除非机主另行拍板豁免并留痕。
3. 清单默认项（对齐 `docs/RELEASE_CHECKLIST.md` 游戏测试节）：兼容版 1936/1939 可进入；完整版 1936/1939 可进入；本轮目标人物/路径显示；动态路径双重验证（按原版逻辑上台**且**上台后显示小传）；无关原版流程未受影响；四份日志判读。

## 三、日志判读口径（裁剪版 check_logs_cbio.py）

- 调用：`python tools/check_logs_cbio.py --logs <游戏日志目录> --round <轮次> --out audit/reports/cbio_<轮次>.json`
- `error.log` 全行白名单过滤；`text.log` 非 0 字节＝本地化错误签名告警；`game.log` 仅对「错误样」行（error/invalid/unknown/exception/failed/warning）告警，正常运行行忽略。
- 白名单起步（`tools/cbio_log_whitelist.json`）：现网已见原版/系统噪声——`virtualfilesystem_physfs.cpp` 缓冲设置失败（gfx 资产）、`Failed to create 2D texture … Not enough memory resources`、`remotefile.cpp … Failed allocate data buffer`、`Conflict Risk` 等；新签名逐条审定后入库或告警。
- `setup.log` 做加载摘要检查（存在性＋`china_bio`/`CBIO` 加载行计数），不过滤。
- **标记铁律不适用**：本 MOD 无 `OCS_TEST` 自检标记，工具不实现标记判定（与爽玩 `--exempt-markers` 等效，工具头注释已注明）；日后若引入自检埋点，再按「标记数＝用例清单数且全 PASS」铁律补实现。
- 游戏版本绑定：读游戏用户目录 `logs\code_revisions.log`（当前 `game_hash_short=a729d47bd`）；绑定失败降级人工登记版本号并记入 result.json。

## 四、脱敏

日志与截图入库前脱敏：本机用户名、绝对路径（`C:\Users\...` 等）替换为 `<REDACTED>`；`D:\SteamLibrary\...` 游戏路径保留（跨机核对已公开该路径口径）。脱敏后的日志副本存入 `logs/`，原始文件不入库；正反斜杠路径变体都要覆盖。

## 五、与既有流程的衔接

- 本制度接入《维护与重构标准流程_适配版》§五：实测完成后先跑 `check_logs_cbio.py` 出 `result.json`，再按本制度归档；归档完成才算该轮实测闭环。
- 实机点验本身仍由机主执行（AI 不代玩）；AI 负责判读、脱敏、归档与报告。日志位置：`<游戏用户目录>\logs\`（路径以《开发状态快照与交接》1.1 为准），AI 直读，机主不用转发。
